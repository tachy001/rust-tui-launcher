# 使用指南

## 语言

进入「设置 → 外观与界面语言」，选中「界面语言 / UI language」后按 Enter，弹出语言列表。用 ↑↓ 选择、Enter 保存并立即切换，Esc 放弃。列表显示原生语言名称、代码和已翻译条数。此项为全局设置，在实例设置中按 G 切换到全局后修改。

可选简体中文 `zh_cn`、英语 `en_us`、繁体中文 `zh_tw`、日语 `ja_jp`、德语 `de_de`、西班牙语 `es_es`、俄语 `ru_ru`、乌克兰语 `uk_ua`、阿拉伯语 `ar_sa`、文言文 `lzh`。十种语言均覆盖当前目录的 220 条文案，包含帮助、任务结果与确认提示；未来缺失文案仍回退到英文。新增翻译尚待母语审校。阿拉伯语提供译文，但终端双向文字、字形连接和从右到左排版仍属实验支持。

「游戏语言」默认 `launcher`（跟随启动器）：以上十种界面语言分别映射到对应 Minecraft 语言代码；文言文在 1.16 之前回退为简体中文。也可单独指定 `zh_cn`、`zh_tw`、`en_us` 等代码。设置为 `keep` 或留空后，启动器保留游戏原语言。实例设置中的游戏语言优先于全局设置，复制实例时保留该设置；按 D 清除实例覆盖后重新继承全局值。

启动前在实际游戏目录（隔离实例或共享目录）的 `options.txt` 更新 `lang`，保留其他选项、原换行和 UTF-8 BOM。1.1–1.10 使用 `zh_CN` 等旧格式，1.11 起使用 `zh_cn`；1.0、Alpha / Beta 或无法确认格式的自定义版本跳过并记录原因。共享同一游戏目录的启动会等待前一个本启动器游戏进程退出，避免运行中改写选项。其他启动器或手动启动的进程不受此锁协调。

命令行临时覆盖示例：`tui-launcher launch 1.21.1 --ui-language en_us --language launcher`；`--language keep` 可单次关闭同步。命令行覆盖不写回配置。

界面翻译目录包含导航、设置、操作提示、编辑 / 确认弹窗和启动器自身任务结果；不同语言的翻译完成度见语言列表。游戏输出、远程项目描述以及底层诊断 / 网络错误保留原文。界面语言不会改变实例名、路径或服务器地址。界面语言使用 auto 时跟随系统，无法匹配时回退英语；翻译资源组织和贡献方式见 [语言包说明](../assets/lang/README.md)。

## 键盘

一级导航只保留五项：**1 账户、2 实例管理、3 实例列表、4 下载、5 设置**。宽终端显示左侧栏，窄终端显示顶部紧凑导航。

回收站、任务日志、Java 检测、整合包导入及 CurseForge 密钥入口位于设置菜单。下面保留原有快捷键作为熟练用户的补充入口。

取消普通下载会保留 `.part` 文件，下次安装继续校验和恢复；网络读取返回前可能需要等待。游戏终止需按 C 后再按 Y。官方 Forge / NeoForge 安装器自身的网络任务不能由本启动器逐文件暂停，取消会结束安装器进程。

## 命令行

```console
tui-launcher --help
tui-launcher doctor
tui-launcher remote 1.21 --snapshots
tui-launcher install 1.21.1
tui-launcher fabric 1.21.1
tui-launcher quilt 1.21.1
tui-launcher forge 1.21.1
tui-launcher neoforge 1.21.1
tui-launcher repair fabric-loader-0.19.5-1.21.1
tui-launcher launch 1.21.1
tui-launcher java-install 21
tui-launcher import MyPack.mrpack my-pack
tui-launcher pack-info MyPack.mrpack
tui-launcher mods my-pack add Example.jar
tui-launcher account offline Player
tui-launcher instance name 1.21.1 "我的原版"
tui-launcher instance clone 1.21.1 my-survival
tui-launcher export my-survival MyPack.mrpack
tui-launcher instance remove my-survival
tui-launcher instance trash
tui-launcher instance restore <回收站ID>
```

`--game-dir <路径>`、`--java <auto或完整路径>`、`--username <名字>`、`--memory <MB>`、`--threads <1-16>`、`--shared`、`--isolated` 可用于本次命令。命令行不会把这些临时覆盖值自动保存。CLI 的 Ctrl+C 取消下载或终止游戏。

下载源可在设置中填写 `official`、`bmclapi`，或兼容 BMCLAPI 路径的 HTTPS 根地址，也可用 `--source` 临时指定。镜像失败会回退原地址，所有原有文件校验保持生效，微软 / Xbox / Minecraft 登录请求不改写。整合包文件的多个 HTTPS 下载地址会依次尝试；用 `--no-optional` 或设置页可不安装整合包标记为可选的客户端文件。

账户操作和应用注册说明见 [docs/AUTHENTICATION.md](AUTHENTICATION.md)。当前没有内置 OAuth 客户端 ID，需自行配置；普通配置只保存账户索引，令牌由操作系统安全存储保管。未选择账户时沿用配置中的离线用户名。

## 配置、目录与日志

### 设置分类与临时覆盖

CLI 的 `--min-memory <MB>` 临时覆盖初始堆，`--min-memory 0` 清除本次指定值，不改变自动最大内存模式，也不写回实例配置。允许范围为 0–65536 MB。

“高级与兼容性”中的最小内存对应初始 Java 堆（`-Xms`），默认 `0` 表示不指定。全局和实例可分别设置，复制实例保留生效值。正数且不超过本次最大堆时才生成默认参数；超过时记录提示并省略，避免自动分配结果较小时发生冲突。自定义 JVM 参数依然参与最终校验，显式设置的初始堆大于最终最大堆会报错。

自动内存参考 HMCL 的可用物理内存分配公式，在选定 Java 后计算建议堆上限；32 位 Java 使用更低上限。系统探测失败会提示并回退到配置的最大内存，不修改保存值。Windows 使用系统接口，Linux 使用 MemAvailable，macOS 通过 Mach 原生接口以空闲和非活跃页估算可用量（空闲统计已含推测页）；后两平台尚未实际运行验收。CLI 的 `--auto-memory` 开启自动模式，`--memory <MB>` 切回手动模式，最后指定者生效。自定义 JVM 内存参数仍由现有参数解析与校验处理，可能覆盖生成的建议值。

设置菜单按用途分为全局游戏设置、Java 管理、通用、外观与界面语言、下载、高级与兼容性；任务日志位于第七项。Java 管理中 V 检测本机 Java；外观页面目前提供语言选择，尚无主题或背景设置。预设尚未实现。自动内存可在全局游戏设置或实例设置中开启；旧配置默认保持手动分配。

全屏、隔离、整合包可选文件和本地库修补按 Enter 直接切换并保存。实例设置中标有“仅全局”的项需按 G 切换到全局修改。窗口宽高可分别覆盖，未设置的维度继承全局值；D 清除的是整个实例覆盖，而不是仅清除当前字段。

`launch` 支持 `--width <像素>`、`--height <像素>`、`--jvm-args <参数文本>`、`--game-args <参数文本>`。这些选项以及 Java、内存、窗口模式和快速游玩选项在本次启动中优先于普通实例覆盖，不写回文件。附加参数文本替换整个对应字段，空字符串表示清空；命令行引号先由当前终端处理，包含空格时应把完整参数文本作为一个命令行值传入。

```console
tui-launcher launch 1.21.1 --memory 4096 --width 1280 --height 720 --windowed
```

服务器和本地存档不能同时作为快速游玩目标。设置页保存时会提示冲突；命令行 `--server` / `--world` 按最后指定的目标切换，并清除另一目标。强制隔离实例仍由后端保持隔离。

新下载的 Java 保存在游戏目录的 `runtime/.tui-managed/`，完成验证后才切换当前记录；旧版 Java 目录仍可发现。更新保留旧运行时，避免影响已运行的游戏或手动指定的 Java 路径。中断准备目录用于续传，历史代及尚未发布的完整目录不会自动删除；目前尚无自动回收功能。

`launcher.json` 位于启动器工作目录，旧版四字段配置仍可加载。设置页保存时原子替换文件。Java 路径使用 `auto`、PATH 命令或完整可执行文件路径，不能附加参数或额外引号；附加参数填写到专门的 JVM / 游戏参数项。

实例设置依次采用全局默认、版本目录 `tui-mc-instance.json` 中随实例保存的设置、`launcher.json` 中该实例的覆盖值。空字符串和 false 可清除上一级选项；整合包或复制实例声明强制隔离时仍使用独立目录。配置文件不存在时使用继承值；文件损坏或无法读取时会显示错误并停止相关操作，请修正提示的文件后重试，启动器不会自动退回共享目录或覆盖原文件。

自定义 JVM / 游戏参数按当前系统解析：Windows 保留普通路径中的反斜杠，支持单 / 双引号分组，例如 `-Dcache=C:\Users\玩家\.minecraft`、`-Dfolder="C:\Program Files\Java"`。双引号前的反斜杠用于转义；双引号内以反斜杠结尾的路径应将末尾反斜杠写成两个，例如 `"C:\folder\\"`。macOS / Linux 保持 POSIX 风格引号与反斜杠转义。配置校验与启动使用同一解析器，不匹配的引号或 NUL 字符会提前报错。参数直接作为 argv 传给 Java，不执行 shell 命令或环境变量展开；只替换启动器支持的占位符。

游戏资源与库共享，存档等数据按隔离设置放置。整合包始终隔离；导入不覆盖已有完整实例，失败后保留标记，可以对同一包和实例名继续导入。新导入的实例有修复记录：删除或损坏 Mod 后可用 X / `repair` 修复，不改变已禁用 Mod 的状态，也不覆盖现有配置修改。仅在文件缺失时恢复配置原值。旧版导入且没有修复记录的实例仍需补回文件或重新导入。

CurseForge 查询需要自己的 API 密钥；API 不提供自动下载地址时可按缺失清单手动补齐。配置方法、缓存说明与验证范围见 [docs/CURSEFORGE.md](CURSEFORGE.md)。

实例显示名称与 ID 分开，改名称不会破坏依赖。复制实例会复制允许的游戏数据目录（含存档），保留启动设置，并以原实例为父版本共享依赖。复制失败可对同一目标 ID 继续。移除采用游戏根目录的 `tui-mc-trash/` 回收站，不永久删除；恢复时不会覆盖同名实例。实例锁放在独立的 `tui-mc-locks/` 目录，防止运行期间移动实例。

整合包导出生成标准索引与 `overrides/`，默认包含 Mod、配置、资源包等，不包含存档、截图、服务器地址以及启动器自身的账户和令牌；导出文件不会覆盖已有文件。未识别的自定义顶层目录不自动打包，避免把无关个人文件带入。导出的依赖会在导入时重新安装，备份不是完全离线的游戏发行包。

游戏日志：`<实际游戏目录>/tui-mc-game.log`，每次启动覆盖；游戏自身日志仍在 `logs/`。安装器日志保存在游戏根目录 `tui-mc-installers/`。账户索引、远程目录缓存位于 `.tui-mc/`。

## 当前限制与开发

尚未接入皮肤管理。在线 Mod 安装已有真实样例，完整依赖自动回溯仍待完善；CurseForge 的真实联网导入没有 API 密钥可验证。旧 Forge 安装器如果没有命令行客户端安装选项会报错，不保证全部历史版本兼容。ARM 原生库与不同操作系统的实际兼容性需要对应平台验收。镜像已实现路径映射和官方回退，网络兼容性仍需验证。

```console
cargo test
cargo clippy --all-targets -- -D warnings
cargo fmt --check
cargo build --release
```

默认测试不连接微软、不写入系统凭证、不启动 JVM 或游戏。需要外部服务的测试单独标记 `ignored`，只在相关流程发生变化并需要验收时手动运行。

后端流程参考了工作区 HMCL 的兼容规则、参数模型与启动流程，以及 PCL 的 classpath / native 参数组织；Rust 实现独立编写，没有复制 Java / VB 源码。参考项目：[HMCL](https://github.com/HMCL-dev/HMCL)、[PCL](https://github.com/Hex-Dragon/PCL2)。


## 网络故障与元数据缓存

成功读取过的版本目录、Fabric / Quilt 列表和配置、Forge / NeoForge 公开版本与校验信息、Java 组件目录会保存在工作目录的 .tui-mc/cache 下。后续请求仍优先联网；镜像数据无效时尝试官方来源，所有来源失败后使用经过校验的缓存并在日志中提示。实时获取成功但缓存不可写时，当前操作可继续，日志会说明缓存未保存。

旧版本保存的 versions.json 缓存仍可读取。取消请求不会转成缓存读取成功；实时数据和缓存均不可用时会同时报告原因。缓存不含账户令牌，也不代表已缓存全部游戏文件：缺少客户端、库、资源或安装器时仍可能需要网络。暂未提供强制离线模式、缓存期限 / 容量管理，实际网络调用的取消响应仍受连接与读取超时影响。


## 安装中断与重试

原版、Fabric 和 Quilt 安装先在实例目录的 .tui-mc-install-drafts 中准备配置和需要下载的客户端，依赖就绪后发布正式配置；已有且校验通过的客户端直接复用。准备失败的新实例不会被当作已安装实例显示；同一配置重试可继续使用已下载的暂存文件。匹配官方 SHA-1 的已有版本 JSON 也可直接复用。

普通提交失败会尝试恢复原客户端；若恢复或清理失败，日志会给出备份位置，后续安装不会覆盖遗留备份。暂存文件便于重试，不要把它们误认为多余的发布包内容。本机制尚不能保证断电 / 强制结束时的完整恢复，也不整体回滚共享依赖或 Forge / NeoForge 官方安装器输出。存在遗留备份时需要核对文件状态后恢复，不能据此直接判断安装成功。


## 提交中途退出后的恢复

使用新版草稿安装时，客户端切换前会保存恢复记录。下次安装、修复或启动该实例，会先检查并恢复记录；读取依赖父版本时也会检查，避免使用混合状态的客户端与配置。新文件均已提交时保留新版本并完成清理，未完成时恢复旧版本并保留暂存下载。

恢复过程中若发现文件已被外部修改、备份损坏或记录不匹配，会停止并保留文件供核对。请不要只删除恢复记录来绕过错误，这会丢失判断文件归属的依据。已验证的是本地进程退出与恢复路径，真实断电、共享依赖整体回滚和 Forge / NeoForge 官方安装器输出恢复仍待完善。旧版本留下的无记录备份不会被自动删除。

## Java 架构与启动前补全

本机检测、手动 Java 路径和托管 Java 校验会读取 JVM 的架构属性。启动日志显示所选 Java 架构；依赖分类、JVM 参数、游戏参数和加载器兼容限制跟随实际 Java，而不是固定使用启动器位数。同一主版本与稳定性内，自动选择优先采用与启动器架构相同的 Java；手动选择不会被擅自替换。

启动前会校验并补齐所选 JVM 对应的依赖，已有且校验通过的文件直接复用。因此改变 Java 位数或架构后，第一次启动可能需要联网下载另一份 native 库；下载失败或取消时不会启动游戏。Java 未提供可识别的 os.arch 或架构 / 位数互相矛盾时会报错，请指定正常安装的 Java。

架构识别不等于全部游戏兼容。现已加入下节所述的 ARM64 已知依赖替换；native 文件内部架构校验、更多兼容补丁及 32 位 JVM 内存限制仍待完善。macOS Rosetta、Windows ARM 仿真和 Linux 不同架构尚未进行真实游戏验收。系统有 Java 可执行，不代表它可加载当前实例的全部原生组件。

## ARM64 原生库兼容替换

使用 ARM64 Java 时，启动器默认对已知的旧版 LWJGL 及原生依赖应用兼容目录，配套更换 Java 库与 native，再校验 / 补下载；正式实例 JSON 保持原样。Windows / macOS 已识别的 1.19+ 基础正式版沿用官方依赖，Linux 的已知 native 可替换为对应 ARM64 变体。未知条目保留并记录提示，已明确提供 ARM64 native 的同坐标库及其 API 保留。

自带原生库的整合包可在 `launcher.json` 设置全局 `"patch_natives": false`，或在该文件 `instances` 下对应实例的设置对象中设置 `"patch_natives": false`；持久实例设置也支持此字段。单次关闭：`tui-launcher launch 1.12.2 --no-native-patches`；单次启用：`--native-patches`。命令行选项不会写回配置，复制实例会保留有效设置。TUI 可在设置 → 高级与兼容性中按 Enter 切换此开关，也可在实例游戏设置中单独覆盖。

部分旧版语音和手柄 native 没有对应 ARM 实现，会从启动依赖禁用并在日志中说明，对应附加功能可能不可用。LWJGL API 版本改变时加入 Sodium 兼容属性；可通过自定义 JVM 参数显式覆盖。目录资源编入程序，发布包仍只需可执行文件；目录说明见 [原生库兼容目录](../assets/NATIVE-PATCHES.md)。

已验证的是本地策略、固定校验字段、预检缓存和解压接入；没有在 ARM 设备上实际运行游戏，也没有下载校验目录的全部真实文件。PE / ELF / Mach-O 内部架构、ABI、第三方原生 Mod 仍需继续处理。

## 历史 Forge 安装与内置库修复

使用原有 Forge 安装入口即可，例如 `tui-launcher forge 1.7.10 10.13.4.1614-1.7.10`。启动器根据官方安装包内部结构选择流程：旧式 universal 包和无处理器的 `spec: 0` Maven 包直接提取内置库、补齐依赖并发布实例，不需要先运行 Java 安装器。其他格式仍执行官方安装器；不能仅凭“1.12.2”等游戏版本判断采用哪条路径。

这两类直接安装生成的依赖记录包含来源安装包及包内条目。以后库丢失或损坏时，修复和启动预检会优先从校验过的安装包恢复，而不是误把整个安装器当作游戏库下载。有效库直接复用；安装包缓存缺失时需联网重新获取，离线时会明确失败。来源或内容校验失败会保留原库，安装草稿不会发布新配置。

安装包缓存位于游戏根目录 `tui-mc-installers/<SHA-1>.jar`，旧名称缓存通过校验后仍可复用。不要把这些游戏运行数据加入 Release 压缩包；发行仍只需可执行文件。新机制不意味着全部历史 Forge 已运行验证：需要客户端合并的更早格式、完整 processor 实现、特殊混装，以及三端真实 Forge / NeoForge 安装与游戏运行仍需完善或验收。

## 安装器与游戏的 Java 要求

运行新版 Forge / NeoForge 安装器前，启动器会读取安装器入口字节码，并结合游戏的 Java 要求选择运行时，日志分别显示这两层下限。安装器由更高版本 Java 编译时，即使游戏只需 Java 8，也会按更高安装需求选择或补装；不会继续下载一个只能满足旧游戏的 Java。已安装且满足要求的 Java 直接复用，手动指定的路径不被自动替换。

自动补装使用启动器已知的 Java 组件；没有覆盖更高版本时，需手动安装并指定合适 Java。取消不会被当作选择 / 下载成功，返回版本不符会中止安装。损坏、清单缺失、重复 ZIP 条目或当前未启用的预览入口会在启动安装器前报告错误。

入口下限检查不是完整兼容证明：依赖库、processor、Java 更新号、厂商差异与特殊 Class-Path / Multi-Release 使用仍可能提出额外要求。旧 / 中间格式直接安装继续无需运行 Java 安装器；三端真实安装仍待验收。
